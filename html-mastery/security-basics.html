42. Security Basics in HTML

While HTML is just a markup language and cannot secure a web application on its own (you need server-side security for that), there are some HTML practices that help prevent common vulnerabilities.

🌐 <head> & <body> Security: <head> policy + <body> attributes
Tag Placement: Web security policies like CSP (<meta http-equiv="Content-Security-Policy">) are placed in the <head> tag, while link security (rel="noopener noreferrer") is applied to <a> tags in the <body> tag.

Code Example

HTML 
<!-- Secure External Link -->
<a
    href="https://example.com"
    target="_blank"
    rel="noopener"
>
    Visit
</a>

<!-- Escaping untrusted data (Don't do this) -->
<!-- <div>Welcome, <script>stealCookies()</script></div> -->

<!-- Do this (Server/Framework escapes the HTML) -->
<!-- <div>Welcome, &lt;script&gt;stealCookies()&lt;/script&gt;</div> -->

Explanation of the Code

  • rel="noopener": When linking to an external site with target="_blank", the new tab can potentially gain access to the original tab's window object using window.opener. noopener prevents this.
  • Untrusted HTML: If your website displays data entered by a user (like a comment), and you don't "escape" the HTML entities (convert < to &lt;), a malicious user could submit a <script> tag that runs bad code on other people's browsers. This is called Cross-Site Scripting (XSS).
