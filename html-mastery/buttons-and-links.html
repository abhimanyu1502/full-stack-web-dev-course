9. Buttons and Hyperlinks

One of the most important decisions in frontend web development is choosing between an anchor link (<a>) and a button (<button>). While both can be styled identically with CSS, they have radically different semantic purposes and accessibility behaviors.

Rule of thumb: Use <a> when navigating to a new page, document, or section. Use <button> when performing an action (submitting data, opening a modal, toggling a menu, or deleting an item).

👁️ <body> Used under tag
Tag Placement: Both <button> and <a> tags belong under the <body> tag as visible, clickable interactive controls.

Key Differences

<a href="..."> Navigation & Locations

Activated by Enter key. Can be bookmarked, opened in new tabs, and indexed by search engines.

vs
<button type="..."> In-Page Actions & Triggers

Activated by both Space and Enter keys. Triggers JavaScript functions and form submissions.

Special Hyperlink Protocols & Attributes

  • mailto:email@example.com: Opens the user's default email client.
  • tel:+1234567890: Prompts smartphones and dialers to initiate a call.
  • target="_blank" rel="noopener noreferrer": Opens a link in a new tab securely without leaking the window.opener object (preventing reverse tab-nabbing attacks).
  • download="filename.pdf": Forces the browser to download the linked file instead of navigating to it.

Syntax

HTML 
<!-- Navigation Link -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">External Site</a>

<!-- Contact Protocol Links -->
<a href="mailto:support@example.com">Email Us</a>
<a href="tel:+18005550199">Call Toll-Free</a>
<a href="/assets/report.pdf" download="Annual-Report.pdf">Download PDF</a>

<!-- Interactive Buttons -->
<button type="button" onclick="alert('Clicked!')">Open Modal</button>
<button type="submit">Submit Application</button>
<button type="reset">Clear Form</button>

Code Example

HTML 
<div class="user-card">
    <h3>Jane Doe — Web Architect</h3>
    <p>Contact Information & Documents:</p>

    <!-- Links for navigation and communication -->
    <p>
        <a href="mailto:jane@example.com">📧 Send Email</a> |
        <a href="tel:+15550100">📞 (555) 0100</a> |
        <a href="/files/resume.pdf" download="Jane-Doe-Resume.pdf">📄 Download Resume</a>
    </p>

    <!-- Buttons for actions -->
    <button type="button" class="btn" onclick="console.log('Followed')">+ Follow</button>
    <button type="button" class="btn-danger" disabled>Block User</button>
</div>

Explanation of the Code

  • mailto: and tel: protocols automatically trigger the corresponding native apps on desktop and mobile devices.
  • download="Jane-Doe-Resume.pdf" instructs the browser to immediately prompt a file download with the specified filename.
  • type="button" prevents default form submission behavior when the button is nested inside a <form>.
  • The disabled boolean attribute renders the button inactive and informs assistive tech that the control cannot be pressed.

Common Mistakes

❌
Using <a href="#"> or <a href="javascript:void(0)"> for actions

Anchors are meant for navigation. Screen readers announce links as "Link," leading users to expect a page transition. Furthermore, keyboard users cannot trigger links with the Space key (only Enter). Always use <button type="button"> for JavaScript actions.

❌
Omitting rel="noopener" on target="_blank" links

Opening external URLs in a new tab without rel="noopener" exposes your website to reverse tab-nabbing security exploits where malicious third-party pages manipulate your original tab via window.opener.

Key Takeaways

Use <a> to go places; use <button> to do things. Always specify type="button" on non-submitting buttons to prevent accidental form submissions.
