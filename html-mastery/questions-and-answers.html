47. Questions and Answers

Test your knowledge with these common HTML interview questions.

🌐 <head> & <body> Interview Q&A: <head> vs <body>
Tag Placement: A classic technical interview question: "What belongs in <head> vs <body>?" The <head> holds document settings and stylesheets, whereas the <body> holds all visible content.
What does HTML stand for?

HTML stands for HyperText Markup Language. It is the standard markup language used to structure and give meaning to content on the World Wide Web. HyperText refers to the system of linking documents via hyperlinks — allowing non-linear navigation between pages. Markup Language describes how HTML uses tags like <h1>, <p>, and <img> to annotate plain text so browsers know how to structure and display it. HTML is not a programming language — it has no loops or conditional logic. It is a declarative, descriptive language that communicates the semantic structure of a document to browsers, search engines, and assistive technologies like screen readers. HTML was invented by Tim Berners-Lee in 1991 and is currently maintained as a living standard by the WHATWG and W3C organisations.

What is the difference between a tag and an element?

A tag is the raw markup notation used to denote the start or end of an HTML structure, wrapped in angle brackets. <p> is an opening tag and </p> is a closing tag. An element refers to the complete unit: the opening tag, all content inside it, and the closing tag together. For example, <p>Hello World</p> is a paragraph element, while <p> and </p> are individually just tags. Some elements are void elements — such as <img>, <br>, and <input> — which have only an opening tag with no closing tag because they cannot contain child content by definition. Understanding this distinction is important when reading HTML specifications, debugging layout issues, and communicating clearly with other developers and tools.

What is an attribute?

An attribute provides additional configuration, metadata, or behaviour for an HTML element. Attributes appear inside the opening tag in name="value" format. For example, in <a href="https://example.com">, the href attribute specifies where the link navigates. Common attributes include: src (source file for images or scripts), alt (text alternative for images), class (CSS styling hook), id (unique identifier), type (input type), placeholder (hint text in inputs), and disabled (disables interaction). Boolean attributes like disabled, checked, and required are activated simply by their presence — no value is needed. Some attributes are global (valid on any element) while others are element-specific. Mastering attributes is essential for building accessible, well-structured, and SEO-optimised web pages.

What is the purpose of DOCTYPE?

The <!DOCTYPE html> declaration must appear at the very top of every HTML document before the <html> tag. Its primary purpose is to tell the browser which version of HTML the document uses and to trigger standards mode rendering. Without a DOCTYPE, browsers fall back to quirks mode — a legacy compatibility mode that emulates inconsistent behaviour from early 2000s browsers. In quirks mode, the CSS box model behaves differently, certain layout rules are ignored, and cross-browser consistency breaks down significantly. Including DOCTYPE also signals to HTML validators and automated tools that the page intends to comply with web standards. The modern HTML5 DOCTYPE is elegantly simple — just <!DOCTYPE html> — compared to the long, complex DOCTYPE declarations required by older HTML versions like XHTML 1.0 or HTML 4.01.

What is the difference between head and body?

An HTML document is divided into two primary sections. The <head> element contains metadata and resources the browser needs to configure the page, but that are not directly visible to users on screen. This includes the document title (<title>), character encoding declaration, viewport settings for responsive design, CSS stylesheet links, JavaScript references, Open Graph tags for social media sharing, and search engine metadata like meta descriptions. The <body> element contains all the visible content that users actually see and interact with — text, headings, images, buttons, forms, navigation menus, and every other rendered element. The browser reads and processes the head first, which is why placing CSS in the head prevents a flash-of-unstyled-content, and why scripts without defer or async in the head can block page rendering.

Why is the alt attribute important on images?

The alt attribute on <img> elements provides a critical text alternative for users who cannot see images, including blind and visually impaired users relying on screen readers. When a screen reader encounters an image, it announces the alt text aloud, allowing users to understand what the image conveys. Beyond accessibility, search engines use alt text to understand and index image content, directly improving image SEO and page relevance scores in results. When an image fails to load due to a broken URL or network error, the alt text is displayed in its place so users understand what was intended. For purely decorative images that convey no information, use an empty alt="" attribute — this tells screen readers to skip the image entirely. Omitting alt entirely is different from an empty alt and may cause screen readers to announce the image filename instead, creating confusing audio output. Providing descriptive alt text is both a WCAG 2.1 accessibility requirement and an established SEO best practice.

What is the difference between ul and ol?

HTML provides two types of list elements. <ul> (unordered list) renders a list where the order of items does not carry meaning, typically displayed with bullet points. Use it for navigation menus, feature lists, ingredient lists, or any collection where sequence is irrelevant. <ol> (ordered list) renders a numbered list where the sequence is significant — step-by-step instructions, ranked items, tutorial steps, or any content where order matters. Both elements use <li> child elements to define each entry. Choosing between them is a semantic decision: using <ol> communicates to screen readers and search engines that order carries meaning. The type attribute on <ol> allows customising numbering style (1, A, a, I, i). Nested lists are created by placing a new <ul> or <ol> inside an <li>. Never use lists purely for visual indentation — use CSS instead.

Why is semantic HTML important?

Semantic HTML means using elements that accurately describe the meaning and role of content, rather than just its visual appearance. For example, using <article>, <section>, <nav>, <header>, <main>, and <footer> instead of generic <div> elements throughout your markup. Semantic HTML provides four major benefits. First, it significantly improves accessibility — screen readers navigate semantic landmarks, announce the page structure correctly, and help users skip to the content they need. Second, it improves SEO — search engines use semantic structure to understand content hierarchy, identify important headings, and determine page topic relevance. Third, it improves developer experience by making code self-documenting and easier to maintain. Fourth, it provides meaningful CSS hooks without cluttering markup with arbitrary class names. The practical rule: if you need a class like class="nav" on a <div>, use the real <nav> element instead.

When should you use a button instead of a link?

Use a <button> when the element triggers an action on the current page — submitting a form, opening a modal dialog, toggling a navigation menu, incrementing a counter, or calling a JavaScript function. Buttons are interactive controls that perform operations in-context. Use an <a> anchor when navigating to a new location — a different page, URL, file download, or an in-page anchor section. The distinction matters greatly for accessibility. Screen readers announce these elements differently, informing users whether to expect navigation or an action. Keyboard users expect Enter to activate both, but Space only activates buttons — not links. Using a styled <div> with an onclick handler instead of a real button is a significant accessibility anti-pattern: these elements are not keyboard-focusable by default, are not announced as interactive controls by screen readers, and require substantial extra ARIA work to fix.

What is the difference between id and class?

Both id and class are HTML attributes that attach identifiers to elements, but they serve different purposes and follow different rules. An id must be unique within a document — no two elements should share the same id value. It is used to uniquely identify a single element for JavaScript targeting, CSS styling, URL fragment navigation (e.g., href="#section-id"), and connecting form labels to inputs via the for attribute. A class can be shared across multiple elements, and a single element can have multiple classes (space-separated). Classes are the primary mechanism for reusable CSS styling and DOM queries. In CSS specificity, an id selector (#id) has significantly higher specificity than a class selector (.class), which can cause cascade conflicts if ids are used heavily in stylesheets. Modern best practice: use classes for all styling, reserve ids for JavaScript hooks and landmark navigation.

Why should labels be connected to form inputs?

The <label> element should always be explicitly associated with its corresponding <input>, <select>, or <textarea>. Association is established either by nesting the input inside the label, or by matching the label's for attribute to the input's id. The benefits are significant and multi-dimensional. For accessibility, screen readers announce the label text when a user focuses the input, providing critical context about what information is expected. Without a label, a screen reader might only say "edit text" with no useful information. For usability, clicking the label text directly focuses or activates the associated input — especially important on mobile where touch targets are small, and for checkboxes and radio buttons where users intuitively click the text rather than the small control. Unlabelled form fields are one of the most common WCAG 2.1 violations and can make forms completely unusable for screen reader and keyboard-only users.

What is the HTTP GET method and when is it used?

The HTTP GET method retrieves a resource from a server without modifying server-side data. When sending a GET request, data is appended to the URL as query parameters — for example, /search?q=html+tutorial&page=2. GET is the default method for HTML forms when no method attribute is specified, and it is the method browsers use when you type a URL and press Enter. GET requests are considered safe and idempotent — making the same request multiple times has no additional effect and should not modify state. Because data appears in the URL, GET requests are bookmarkable, shareable, and cached by browsers, making them ideal for search queries, page navigation, and filtering. However, GET must never be used for sensitive data like passwords because URLs appear in browser history, server logs, and HTTP referrer headers transmitted to third-party sites.

What is the HTTP POST method and when is it used?

The HTTP POST method submits data to a server to create or modify a resource. Unlike GET, POST sends data in the request body rather than the URL, making it suitable for sensitive or large data — user registrations, login credentials, form submissions, file uploads, and payment information. POST requests are not idempotent — repeating the same POST request may create duplicate records or trigger duplicate actions, which is why browsers display a warning when you refresh a page loaded via POST. Because data is not in the URL, POST is more discreet, but requests are not directly bookmarkable or shareable. In HTML, you specify POST with <form method="post">. In REST API design, POST typically creates new resources while PUT or PATCH update existing ones. Always use POST whenever a user action has server-side consequences such as writing to a database or sending an email.

What is ARIA and why is it important?

ARIA (Accessible Rich Internet Applications) is a W3C specification of HTML attributes that adds semantic information to elements, making dynamic web content and custom UI components accessible to users with disabilities. ARIA provides three categories of attributes. Roles describe what an element is — for example, role="dialog", role="tablist", or role="alert". States describe the current condition of an element — aria-expanded="true", aria-checked="false", or aria-disabled="true". Properties provide additional context — aria-label="Close menu", aria-describedby="error-message", or aria-live="polite" for dynamic content announcements. The cardinal rule of ARIA is: "No ARIA is better than bad ARIA" — incorrectly applied ARIA can make a site less accessible than without it. Always prefer native semantic HTML elements first, since they have built-in accessibility semantics built directly into the browser.

What is lazy loading and how does it improve performance?

Lazy loading is a performance optimisation technique where non-critical resources — primarily images and iframes — are deferred and only loaded when they are about to become visible in the user's viewport, rather than loading everything when the page initially renders. In HTML, lazy loading is enabled by adding the loading="lazy" attribute to <img> or <iframe> elements — no JavaScript required. The performance benefits are substantial: significantly reduced initial page load time and data consumption; improved Core Web Vitals scores (particularly LCP — Largest Contentful Paint and FID — First Input Delay); and lower server bandwidth costs. Lazy loading is especially valuable for long-scrolling pages with many images. Resources that are immediately visible in the viewport (above-the-fold content) should always use loading="eager" or omit the attribute to avoid delaying critical content. Browser support is now excellent across all modern browsers.

What is the DOM?

The DOM (Document Object Model) is the browser's live, in-memory object representation of an HTML document as a hierarchical tree of nodes. When a browser parses an HTML file, it constructs the DOM — a structured tree where each HTML element, text node, attribute, and comment becomes an object with properties, methods, and parent/child relationships. The DOM is entirely separate from the original HTML source file and can be dynamically modified by JavaScript at runtime without changing the actual file. For example, document.querySelector('h1').textContent = 'New Heading' updates the DOM immediately, changing what the user sees. All frontend interactivity operates on the DOM: event listeners, style manipulation, element creation, removal, and reordering. The DOM combines with the CSSOM (CSS Object Model) to form the render tree, which the browser's layout and paint engines use to determine the final visual output on screen.

What does the defer attribute on a script tag do?

The defer attribute on a <script> tag instructs the browser to download the script file in the background while HTML document parsing continues, then execute the script only after the entire HTML document has been fully parsed — but before the DOMContentLoaded event fires. Without defer, a script encountered during HTML parsing causes the browser to completely halt parsing, download the script, execute it, and only then resume parsing the remaining HTML. This is called render-blocking and significantly delays initial page display. The defer attribute also preserves execution order — multiple deferred scripts execute in document source order, unlike async which executes each script as soon as it downloads regardless of order. Best practice for application scripts: use defer in the <head> for clean document organisation, or place scripts at the bottom of <body>. Reserve async for fully independent scripts like analytics tracking.
