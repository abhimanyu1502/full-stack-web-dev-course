1. Introduction to HTML

HTML stands for HyperText Markup Language. It is the foundational standard language used to create and structure content on the World Wide Web. Every website you visit — from a simple personal blog to complex web applications like Gmail or GitHub — is ultimately built on HTML at its core.

HTML exists to tell the browser what each piece of content means and how the page is structured semantically. Think of a webpage like a building: HTML provides the architectural structure (the walls, floors, and rooms), CSS provides the interior design and presentation (paint, furniture, decorations), and JavaScript provides the behaviour and interactivity (electricity, plumbing, automated systems).

HyperText refers to the foundational concept of hyperlinks — the ability to link from one document to another anywhere on the web, creating the interconnected network of information we navigate daily. This linking capability, invented by Tim Berners-Lee in 1991 at CERN, is what transformed isolated documents into the World Wide Web.

Even if you eventually use modern JavaScript frameworks like React, Vue, Angular, or Svelte, they all ultimately generate HTML for browsers to interpret and render. React components compile down to HTML elements. Vue templates produce HTML markup. Angular renders to the DOM. Understanding raw HTML deeply means you will always understand what your tools are producing, giving you a significant advantage when debugging, optimising performance, or ensuring accessibility compliance.

🌐 <head> & <body> Structure: <head> & <body>
Tag Placement: In HTML documents, tags are divided into two primary zones: <head> tags (e.g. <title>, <meta>, <link>) configure invisible metadata, while <body> tags (e.g. <h1>, <p>, <div>) contain all visible content rendered to the user.

Syntax

HTML is a markup language, meaning it uses "tags" to wrap content and give it meaning. A basic element looks like this:

HTML 
<tagname>Content goes here...</tagname>

Code Example

HTML 
<h1>Hello World</h1>
<p>This is my first webpage.</p>

Explanation of the Code

  • <h1> is an opening tag that defines a large heading. The text "Hello World" is the content.
  • </h1> closes the heading element. The forward slash / indicates it is a closing tag.
  • <p> defines a paragraph of text.
  • The browser reads these tags and translates them into a visual representation for the user.

Why This Matters in Professional Development

Understanding HTML deeply — not just superficially — separates junior developers from senior frontend engineers. Many developers skip HTML fundamentals and jump straight into JavaScript frameworks, leading to common problems they can't diagnose: poor accessibility scores, search engine penalties for missing semantic structure, and layout bugs caused by invalid nesting.

Here is why HTML mastery is indispensable even in a modern framework-dominated world:

  • Accessibility compliance: Screen readers, keyboard navigation, and assistive technologies depend entirely on proper HTML structure. Frameworks do not automatically make sites accessible — developers must understand semantic HTML to write inclusive code. WCAG 2.1 compliance, required by law in many jurisdictions, is built on a foundation of correct HTML.
  • Search engine optimisation (SEO): Search engines crawl and index your HTML source. Proper heading hierarchy (<h1> through <h6>), semantic elements (<article>, <main>, <nav>), structured data (JSON-LD), and meaningful link text all directly influence how and whether your pages appear in search results.
  • Performance optimisation: How you write HTML affects Core Web Vitals. Render-blocking scripts, missing loading="lazy" attributes on images, absent srcset attributes for responsive images, and bloated DOM trees all degrade performance scores measured by Google's PageSpeed Insights and Lighthouse.
  • Maintainability and team communication: When HTML is written semantically, code becomes self-documenting. Other developers, designers, and QA engineers can understand the page structure without needing to decode layers of JavaScript logic.

Common Mistakes Beginners Make

Awareness of common mistakes accelerates learning and helps you write better HTML from day one:

  • Using <div> for everything: Overusing generic container elements like <div> and <span> instead of semantic elements like <section>, <article>, <nav>, <aside>, and <header> is called "div soup." It makes code harder to understand and harms accessibility and SEO.
  • Skipping or duplicating heading levels: Jumping from <h1> directly to <h4> or using multiple <h1> tags on a single page disrupts both the document outline used by assistive technologies and the content hierarchy signals that search engines rely on.
  • Missing alt attributes on images: Every <img> element must have an alt attribute. Omitting it fails WCAG accessibility standards and prevents search engines from understanding image content. Use descriptive text for informative images and alt="" for purely decorative ones.
  • Using deprecated HTML attributes for styling: Older HTML used attributes like bgcolor, align, border, and font tags for visual styling. All styling should be done with CSS, keeping content and presentation properly separated.
  • Unclosed or improperly nested tags: Forgetting to close elements or nesting elements incorrectly (like placing a <p> inside another <p>) causes the browser's HTML parser to apply error recovery rules, which can produce unexpected layouts across different browsers.

How Browsers Parse and Render HTML

When a browser receives an HTML file from a server, it goes through a multi-stage rendering pipeline:

  • 1. Tokenisation: The browser reads the HTML byte-by-byte and converts the character stream into tokens — start tags, end tags, attribute tokens, and text content.
  • 2. Tree Construction (DOM): Tokens are processed into a tree of objects called the Document Object Model (DOM). Each HTML element becomes a node in this tree with parent-child relationships reflecting the document structure.
  • 3. CSS parsing (CSSOM): Simultaneously, the browser parses linked stylesheets and style tags to build the CSS Object Model (CSSOM), a tree of style rules.
  • 4. Render Tree: The DOM and CSSOM are combined into a render tree containing only visible nodes with their computed styles applied.
  • 5. Layout: The browser calculates the exact position and size of every element on screen based on the render tree and viewport dimensions.
  • 6. Paint and Composite: Elements are drawn to screen layers and composited together into the final visible page.

Understanding this pipeline explains why certain HTML choices matter for performance — for example, why large inline scripts in the <head> delay the first render, why missing width and height attributes on images cause layout shifts (CLS), and why the order of stylesheets relative to scripts matters.
